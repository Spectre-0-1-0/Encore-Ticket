# 🔐 Multi-Layer Cryptographic Specification

> **Document Version**: 1.0.0  
> **Module**: `src/lib/cryptoEngine.ts`  
> **Security Objective**: Multi-tier obfuscation, PII privacy protection, and tamper-evident authentication.

---

## 1. Overview of the 4-Layer Cryptographic Pipeline

The cryptographic pipeline converts plaintext student profile JSON into a high-density, uninterpretable Hexadecimal string for QR rendering, and vice-versa for authorized scanning.

```
+-----------------------------------------------------------------------+
|                     ENCRYPTION PIPELINE (STUDENT WEB)                 |
+-----------------------------------------------------------------------+
|  Plaintext JSON Payload:                                             |
|  {"roll":"2024CS01","name":"Pavan Kandala","email":"pavan@ex.com"}     |
|                                                                       |
|  Layer 0: HMAC-SHA256 Integrity Hash                                  |
|  ├── Signature = HMAC_SHA256(Plaintext, HMAC_SALT)                    |
|  └── Full Payload = JSON.stringify({ data: Plaintext, hmac: Sig })    |
|                                                                       |
|  Layer 1: AES-256-CBC Encryption                                      |
|  ├── Key: AES_SECRET_KEY (256-bit / 32 chars)                         |
|  └── Cipher 1 = AES_Encrypt(Full Payload, Key, IV)                    |
|                                                                       |
|  Layer 2: Triple-DES-CBC Encryption                                   |
|  ├── Key: 3DES_SECRET_KEY (192-bit / 24 chars)                        |
|  └── Cipher 2 = 3DES_Encrypt(Cipher 1, Key, IV)                       |
|                                                                       |
|  Layer 3: Bitwise XOR Array Mask Shift                                |
|  ├── Mask: XOR_BYTE (e.g. 0x5A)                                       |
|  └── Transformed Bytes = Apply Byte[i] ^ Mask for each byte          |
|                                                                       |
|  Layer 4: Hexadecimal Encoding                                        |
|  └── Final QR Data = Uppercase Hexadecimal String (e.g. A3F8120C...)  |
+-----------------------------------------------------------------------+
```

## 2. Layer-by-Layer Technical Specification

### Layer 0: Integrity Checksum (HMAC-SHA256)
- **Algorithm**: `HMAC-SHA256`
- **Salt / Secret**: `NEXT_PUBLIC_HMAC_SALT`
- **Purpose**: Appends a cryptographically secure message authentication code (MAC) to detect any payload tampering before processing.
- **Payload Structure**:
  ```json
  {
    "p": {
      "roll": "2024CS01",
      "name": "Pavan Kandala",
      "email": "pavan@example.com",
      "ts": 1770000000
    },
    "h": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
  }
  ```

### Layer 1: Symmetric Block Cipher (AES-256-CBC)
- **Algorithm**: `AES-256-CBC` (Advanced Encryption Standard, 256-bit key)
- **Key**: `NEXT_PUBLIC_AES_SECRET_KEY` (32 bytes)
- **Padding**: `PKCS7`
- **Purpose**: Provides primary military-grade confidentiality and data protection for PII elements.

### Layer 2: Secondary Cipher (Triple-DES-CBC)
- **Algorithm**: `Triple-DES-CBC` (3DES / TDEA, 192-bit key)
- **Key**: `NEXT_PUBLIC_3DES_SECRET_KEY` (24 bytes)
- **Padding**: `PKCS7`
- **Purpose**: Introduces a secondary algorithmic layer of cryptographic depth to prevent single-cipher automated analysis.

### Layer 3: Custom Bitwise XOR Array Transform
- **Operation**: `Byte[i] = Byte[i] ^ XOR_MASK`
- **Byte Mask**: `NEXT_PUBLIC_XOR_SHIFT_BYTE` (e.g. `0x5A` or `90`)
- **Purpose**: Obfuscates standard Base64/ASCII headers (`U2FsdGVk...`) generated by standard CryptoJS output, breaking automated algorithm fingerprinting.

### Layer 4: Hexadecimal Stream Formatting
- **Encoding**: Binary/ASCII Array to Uppercase Hexadecimal String
- **Format**: `[0-9A-F]+` (e.g. `584F523A...`)
- **Purpose**: Converts the binary array into a clean alphanumeric string optimal for high-density QR code rendering across web canvas and camera readers.

## 3. Reverse Decryption Pipeline (Admin Scanner)

The Admin Scanner App executes the exact reverse sequence:

```
[ Captured Hex QR Stream ]
           │
           ▼
[ 1. Parse Hex String ] ──────► Reconstructs raw byte array / string
           │
           ▼
[ 2. Bitwise XOR Unmask ] ────► Applies XOR_BYTE mask to restore Layer 2 string
           │
           ▼
[ 3. Triple-DES Decrypt ] ───► Decrypts using 3DES_SECRET_KEY to yield Layer 1 string
           │
           ▼
[ 4. AES-256 Decrypt ] ──────► Decrypts using AES_SECRET_KEY to yield Layer 0 JSON
           │
           ▼
[ 5. HMAC Validation ] ──────► Computes HMAC of 'p' payload with HMAC_SALT
           │
           ├── Signature Match: Valid ticket! Output student data.
           └── Signature Mismatch: THROW "TAMPERED / CORRUPTED TICKET"
```

## 4. Test Vector Integrity & Verification Matrix

| Step | Input Format | Output Format | Success Criteria |
| :--- | :--- | :--- | :--- |
| **Layer 0** | Student JSON Object | Signed JSON string with `h` hash | HMAC length == 64 hex chars |
| **Layer 1** | Signed JSON string | AES-256 Cipher Text | Cipher begins with valid encrypted block |
| **Layer 2** | AES Cipher Text | Triple-DES Cipher Text | Double-encrypted string |
| **Layer 3** | Triple-DES Cipher Text | XOR Masked String | ASCII signatures (`U2F...`) removed |
| **Layer 4** | XOR Masked String | Uppercase Hex String | Matches regex `^[0-9A-F]+$` |
